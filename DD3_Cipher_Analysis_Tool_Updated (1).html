Classical polyalphabetic

Vigenère

A substitution cipher that uses a repeating keyword. Each plaintext letter is shifted by the alphabet position of the corresponding key letter. This produces changing shifts rather than one fixed substitution. It is useful for learning classical cryptography, but it is not secure by modern standards.

Tool convention: A=0 through Z=25; key letters repeat; non-A–Z characters remain unchanged and do not advance the key.

Modern authenticated encryption

AES-256-GCM

A symmetric authenticated-encryption mode using AES with a 256-bit key. GCM provides confidentiality and an authentication tag that detects changes or a wrong key. This tool generates a fresh 96-bit nonce for each encryption and stores it with the ciphertext. Decryption requires the same key, nonce, and unmodified encrypted data.

Tool envelope: AES256GCM:v1:IV-base64:ciphertext-and-tag-base64.

Classical monoalphabetic

Caesar

A substitution cipher that shifts every alphabetic letter by the same fixed number of positions. The assignment's chosen demonstration setting is a shift of 3. It is simple to implement and explain, but very easy to break by trying the 25 possible non-zero shifts.

Tool convention: preserves case and non-letter characters; shift can be set from 0 to 25.

DD1 / DD2 formats observed in Communication_Logs.csv

DD1 (observed): DD1:<ciphertext>. The dataset shows this prefix followed by alphabetic text. This workbench treats the payload as Vigenère ciphertext because T1 requires Vigenère support. Compare with the professor’s separate reference page or ask the Senior Analyst to confirm the exact DD1 convention.

DD2: DD2.<MessageID>.<NonceHex>.<TagHex>.<CiphertextBase64URL>. The observed nonce is 12 bytes (24 hex characters), the authentication tag is 16 bytes (32 hex characters), and the ciphertext uses unpadded Base64URL. The embedded MessageID matches the CSV MessageID field in all observed DD2 rows.

The dataset reveals the envelope layout, not the secret keys. It also does not establish whether MessageID is AES-GCM additional authenticated data (AAD); the tool offers both choices. The separate reference page was not included in the uploaded materials, so confirm the exact DD1/DD2 rules, keys, and AAD setting with your Senior Analyst before decrypting the actual logs.
